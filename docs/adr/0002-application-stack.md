# Application stack for the MVP

Use Django 5.2 LTS with server-rendered pages, PostgreSQL, and a database-backed worker in the same codebase. Run the finished internal tool on an organization-controlled machine or VM that employees can reach over the internal network or VPN. Django's migrations, transactions, forms, and session handling suit the eight vertical slices without a separate frontend service. PostgreSQL can enforce the uniqueness and transactional rules for versions, assignments, and delivery work. A database-backed worker avoids an additional queue service.

The organization uses Microsoft Entra ID for employee accounts. Keep authentication as a development stub while building core workflows; choose and implement the final Entra account-binding procedure before real employee use. Likewise, use a local email sink while building notification behavior, then connect an organization mail relay or another provider before live use. Provider credentials, the application URL, and sender details remain runtime configuration.

Local development needs no paid hosting: run the application, PostgreSQL, and worker on the developer's machine and use an email sink while building notification behavior. An internal deployment also needs no new hosting subscription if an always-on organization-controlled host, network access, TLS, backups, and an operational owner are available. This avoids Render's paid worker and [short-lived free database](https://render.com/docs/free). Existing infrastructure still has operating costs. Use synthetic employee data until the real-data gate in the [implementation plan](../implementation-plan.md#planning-assumptions-and-decisions) is met.

An external identity service is unnecessary because the organization already uses Entra ID. [Resend pricing](https://resend.com/pricing) includes a free tier, and its [idempotency keys](https://resend.com/changelog/idempotency-keys) do not remove the need for delivery reconciliation beyond their retention window. The internal host must meet Django's [deployment checklist](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/) before employees use it.
